# Vibe Release Example: ChatGPT Model Inspector

这是 Vibe Coding 小工具发布流程的第一个实践案例。

注意：这个文件不是发布规则本身，而是一个案例记录，用来说明一套通用规则如何应用到真实项目。

## 项目背景

项目：ChatGPT Model Inspector

问题：

每次查看 ChatGPT 返回的 `model_slug`，需要手动打开 F12 → Network → 查找请求 → 搜索字段。

解决方式：

制作一个轻量浏览器扩展，将可观察到的 `model_slug` 直接显示在页面中。

## README 结构案例

采用产品说明优先，而不是纯技术文档：

1. 一句话说明解决什么问题。
2. 30 秒看懂工作流程。
3. 为什么做这个工具。
4. 它能做什么 / 不能做什么。
5. 示例图片和状态展示。
6. 安装方法。
7. 技术说明和限制。

## 截图策略案例

展示三个核心状态：

### Normal

正常检测状态。

目的：证明工具正常工作。

### Warning

检测到特殊命名或风险提示状态。

目的：展示工具不仅显示结果，也提供反馈。

### Empty / Waiting

等待响应或没有检测结果状态。

目的：展示边界情况。

## Release 结构案例

Release 不重复 README，而关注版本变化：

- 新增了什么。
- 修复了什么。
- 如何安装。
- 当前限制。

## 可迁移经验

这个案例总结出的通用经验：

- 小工具也需要产品化表达。
- GitHub 面向长期可信使用。
- 社交媒体面向发现和传播。
- 截图优先展示用户能理解的状态，而不是代码实现。
- 缺少真实状态截图时，可以使用标注清楚的示意图作为补充。
